# Vibe Prompting：把生成提示词写成状态程序

生成模型读提示词的方式接近读代码：先找到对象，再按顺序执行每一步。提示词应当写成一段**状态程序**，而不是一段氛围描写。这套写法和模型无关，各模型只是字段名不同。

本文所有示例均为通用示例，不对应任何具体项目。

## 核心：只给已声明的对象赋值

整套写法的根是这一条：**本段没有声明的对象，不能给它写动作、状态或台词。**

正文里写「服务员把杯子推过来」「有人说：……」「其他客人低头喝咖啡」，而这些人在本段开头没有声明，模型就找不到这句话的承载者。常见结果有两种：

- **整句或整段被当成语音念出来**，或者台词落到画面里唯一已声明的那个人嘴上；
- 模型临时造一个人来执行，表现为乱入、换脸。

所以写每一句之前先问：这句话的主语，本段声明过了吗？没有就先声明，或者删掉这句。其余规则（状态衔接、肯定句）都建立在这一条之上。

## 编程词只是类比，不写进提示词

本文用「声明、赋值、作用域、import、S0 / a1」帮助理解模型的执行方式。**这些词只用于思考和排查，提示词正文一律写成普通的画面描述。**

| 类比 | 提示词里实际写的是 |
| --- | --- |
| 声明一个对象 | 「`<Subject 2>` 是咖啡馆服务员，本段双手与小臂入画。」 |
| 赋初值 S0 | 「她坐在靠窗桌边，双手放在桌面。」 |
| S1 = S0 + a1 | 「她双手撑桌站起来，站在桌边。」 |

不要在提示词里出现 `import`、`declare`、`S0`、`a1`、「变量」「赋值」「环境库」「作用域」这类词。写进去模型不会当成指令，只会当成要画或要念的文字。

## 基本模型

三个概念：

- **对象**：画面里出现的人或物。
- **状态**：某一时刻对象的可见属性：位置、姿势、朝向、接触、门的开合、光。
- **动作**：作用于当前状态、得到下一个状态的一步变化。

状态按赋值计算：

```text
S0 = 初始状态
S1 = S0 + a1
S2 = S1 + a2
```

通用示例：

```text
S0 = 她坐在椅子上
S1 = S0 + 站起来        → 她站在椅子前
S2 = S1 + 走向门口      → 她站在门口
```

写成提示词：

```text
她坐在椅子上。她站起来，站在椅子前。她走向门口，停在门口。
```

## 五条规则

**1. 先声明，后使用。** 本段画面里出现的每个对象，以及画面外说话的人，开头先写明身份、来源和可见范围（全身、上半身、仅双手）。每次生成都是独立的一段，不继承上一段的声明。

（类比：声明像程序里的 import。以下只是帮助理解，提示词里不写这些词。）

| 写法 | 类比 | 风险 |
| --- | --- | --- |
| 上传 `<Picture N>`，`<Subject N>` 写明来自该图 | 带文件的 import，外观锁图 | 低 |
| 无图，只在 `subject_definitions` 用文字写清 `<Subject N>`（身份、服装、本段可见范围） | 不带文件的 import，模型按名字补外观 | 低（一致性弱于有图，但可控） |
| 正文里出现「服务员 / 一只手 / 有人说」，本段却没定义 | 未声明就使用 | 高：乱入、换脸、**整段被念成语音** |

**没参考图不可怕，可怕的是没声明。** 缺图时用文字把对象写进 `subject_definitions` 即可。

**声明越笼统，模型补得越多。**

| 粒度 | 声明写法 | 效果 |
| --- | --- | --- |
| 粗 | 「有个服务员」「一只手」 | 易附带整张脸、制服、**默认会说话的声线**，跨镜不一致 |
| 细 | 「咖啡店服务员，本段双手与小臂入画，只做放杯」 | 只出现本镜需要的部分，幻听与乱入少 |
| 最细 | `<Picture N>` + 同上可见范围与动作 | 外观与范围同时锁住 |

正文也只写声明里有的部分：声明了只露双手，正文就不要写脸。

**2. 动作只从当前状态出发。** 每个动作都有前置条件。坐着的人不能直接走，门关着时不能直接穿过门。前置条件不满足时，补上缺的那一步：先站起来，先开门。

**2.1 行为与状态不得冲突。** 同一角色、同一段里，**当前状态**与**后续动作**必须是同一套事实。初态里已经成立的姿势，后面不能再写与之矛盾的动词；也不能写「进入」一个已经在的状态（模型会再演一遍，画面违背逻辑）。

| 当前状态（已赋值） | 禁止再写 | 应写 |
| --- | --- | --- |
| 躺在地上 | 走路、迈步 | 先写翻身、撑地坐起，再写站起与移动 |
| 已躺在地上 | 「躺下了」「倒在地上」 | 只写在这一姿势下的动作（抬手、转头） |
| 桌上已有空杯 | 「放下一杯」「又拿来一只杯」 | 「往空杯里倒水」「把杯口转向客人」 |
| 已坐在靠窗的桌边 | 「请她入座」「按进座位」 | 「把菜单放到桌面」「她翻开菜单第一页」 |
| 背包已背在肩上 | 「背上背包」「把包挂到肩上」 | 「调整肩带」「拉开侧袋拉链」 |

写每一句动作前问：**这一秒的姿势是什么？** 动作只能改变它，不能假装它还是上一镜或未声明的状态。

**3. 每个动作后写出新状态。** 改变状态的动作，紧跟写出结果：「她站起来，站在椅子前。」不要只写结果（直接跳到 S2），也不要只写动作不写结果。

**4. 没有改变的属性保持不变。** 同一段里，门开着就一直开着，不用每句重复。换到新的一段时，把延续下来的属性在开头重新写一遍。

**5. 只用肯定赋值。** 写对象**是什么**，不写**不是什么**。否定词会把被否定的东西带进画面。只有三处允许出现否定：台词标记内（如 H3 的 `<d>…</d>`）、画面内可见文字、表示「无配乐」的 `none` / `N/A`。其余正文一律正面赋值。模型有独立负面栏时，排除项只放负面栏。

一段只放几步动作。步骤多到一段做不完时，在一个稳定状态处拆成两段。

## 写作流程

1. 列出本段画面里的对象，逐个声明。
2. 写出初始状态 S0，申明这一镜开始时看得见的状态。拆成此刻的姿势和物件。不写「端坐」「捧杯」「背手」这类概括词；写「她坐在椅上，双脚平放，双手放在膝上」。
3. 列出动作序列。逐条检查前置条件与 **2.1 行为/状态不冲突**，缺的动作补上，与初态矛盾的动词改掉。
4. 每一步写成「动作，新状态」。
5. 记下末状态 S_end。下一段如何接：
   - **硬切**：把 S_end 原样写成新段的 S0（完整申明）。
   - **引导上端**（上一段末 22 帧）：S0 已由上端画面绑定，新段可省略或极简初态，**只写 S_end 之后的新动作**；若写初态，必须与上段末帧一致，否则接点会切镜、跳变。
6. 按目标模型的字段格式输出（见「输出到具体模型」）。

## 句式

```text
声明：A 是[身份]，来自[参考图]，本段可见[全身 / 上半身 / 双手与肩]。
初态：A 在[位置]，[姿势]，[朝向]。
一步：A [动作]，[新状态]。
```

一句一个主语。多个对象同时动作时，分句写，每句写清是谁。

## 改写对照

| 原句 | 问题 | 改写 |
| --- | --- | --- |
| 她坐在椅子上。她走到门口。 | 坐着不能走，缺「站起来」 | 她坐在椅子上。她站起来，站在椅子前。她走向门口，停在门口。 |
| 她坐在桌边。她已经站在门外。 | 跳过中间状态 | 她坐在桌边。她站起来。她走向门口，拉开门。她走出门，站在门外。 |
| 房间里没有别人。 | 否定句 | 房间里只有她一个人。 |
| 他不说话。 | 否定句，还会引出说话 | 删掉这句，不给他 `<d>`。若有画外声，在初值写一次「他嘴唇闭着，是画外声的听众」 |
| 一只手按住她的肩。（手的主人未声明） | 未声明 + 粗粒度 | 先声明 B，本段可见双手与肩；再写「B 的双手按住她的肩」。 |
| 服务员把杯子放到她面前。（未写可见范围） | 声明太笼统，模型补出整个人 | 声明 B 双手与小臂入画 + 动作职责；不上传脸时也不要在正文要脸。 |
| 新一段：她推开门。（未写初态） | 新段没有 S0 | 她站在门前，右手握着门把。她推开门。 |
| 她躺在地上。她迈步走向门口。 | 躺着与走路冲突 | 她躺在地上。她撑地坐起，再跪起、站起，然后走向门口。 |
| 她已躺在地上。她躺下了。 | 重复进入同一状态 | 她躺在地上。她转头看向门口。 |

## 声音

- 说话的人必须是已声明的对象（画面外的服务员、旁白者也要声明，写明不入画、由它承载对白）；台词只进该对象的 `<d>…</d>`。
- 有画外声时，画面里听的人在初值里写一次「嘴唇闭着，是该画外声的听众」，之后的动作句不再写嘴唇。没有画外声、只有一个人时，不写嘴唇。
- 动作句里不写「该句为画外声」等解释句，那是教程，不是状态。
- 环境声（脚步、风、关门）写在声音字段，不写进人物的动作句。

## 输出到具体模型

先按上面的规则写好逻辑，再换成目标模型的格式。逻辑不变，只换字段名。

| 逻辑 | MiniMax H3 Ref2VA | MiniMax H3 T2VA / I2VA | 其他模型（Kling、Seedance、Veo、Sora 等） |
| --- | --- | --- | --- |
| 声明变量 | 上传参考图 + `subject_definitions` | 描述第一句先锚定主体 | 开头写「@Image1 是…」或点名参考图 |
| 初值 S0（申明镜头开始状态） | `retention_analysis`：级别是锁的松紧，`fully_preserved` 等于这一主体的 I2V，`weak_reference` 等于自由发挥。破折号后写「当前状态：」加此刻看得见的姿势和物件 | `[Shot 1]` 开头，同样写成看得见的事实。I2VA 的首帧图即最强初值 | 主提示词开头 |
| 注释 | `summary`（不写「说」等说话动词） | — | — |
| 状态转移 | `detailed_description` 的 `[Shot 1]`，起句复述同一初值 | `integrated_multimodal_description` 的 `[Shot 1]` | 主提示词，按时间顺序 |
| 环境声 | `overall_soundscape` | `overall_soundscape` | 模型的音频描述位置 |
| 无配乐 | `non_diegetic_music: none` | `non_diegetic_music: N/A` | 该模型表示无配乐的写法 |
| 排除项 | 无负面栏，只能肯定赋值 | 同左 | 有 `negative_prompt` 才放那里 |

各模型的时长、运镜词、台词标记以该模型自己的写法规范为准。

## 排查：当作调试程序

H3 的行为与控制逻辑与**顺序程序**同构。出问题时不要先改形容词，按下面逐项查，和查代码一样。

| 现象 | 编程类比 | 查什么 |
| --- | --- | --- |
| 成段文字被念成语音、乱入的人、换脸 | 未声明就使用 | 正文和 summary 里每个主语（含画外说话的人、「一只手」「其他客人」）本段是否声明过 |
| 幻听、旁白被念出来 | 字符串误进可执行区 | `summary` / 运镜句里是否含「说」类词；台词是否只绑在带 `<d>` 的 Subject |
| 动作跳变、姿势矛盾 | 状态与语句不一致 | 当前状态 + 动作是否满足 2.1；是否缺中间步（S0 不能走却写走） |
| 重复执行同一步 | 对已在的状态再赋值 | 是否写「进入」已在的状态（已躺又「躺下」、已有杯又「放杯」） |
| 硬切接不上 | 新作用域未初始化 | 硬切段是否完整写 S0；是否误继承上段声明 |
| 有引导仍切镜 | 与 I2V 输入冲突 | 引导段是否强绑与上端末帧不符的「当前状态」 |
| 「不要 X」却出现 X | 否定写在错误层 | 否定是否只在 `<d>` / 画面内文字 / `none` |
| 字段乱、模型当音频 | 键名/顺序不是语法 | Ref2VA 六段顺序、秒数是否只写在标题外 |

**调试顺序：** 作用域（本段声明）→ 初值（硬切 full / 引导 minimal）→ 逐步执行（每句能否从上一状态推出）→ 副作用分层（声在哪个字段）。

## 自检

- 正文里每一句的主语（包括画外说话的人、「一只手」「其他客人」），本段开头都声明了吗？声明粒度是否只覆盖本镜实际用到的部分？
- 提示词里有没有混进 `import`、`S0`、「变量」「环境库」这类类比用词？
- 每个动作的前置条件，在上一状态里都成立吗？初态与动作有没有冲突（躺着却走、桌上已有杯却又「放杯」、已躺平却又「躺下」）？
- 每个改变状态的动作后面，都写出新状态了吗？
- 删掉任意一句，下一句还推得出来吗？推得出来说明多余；推不出来说明它是必需的一步。
- 新一段是硬切还是引导上端？硬切是否完整写出 S0？引导段是否避免与上端帧矛盾的强绑初态？
- 否定词只出现在台词标记、画面内文字、`none` / `N/A` 里吗？

## 通用示例（完整）

```text
# 散文写法
安静的咖啡馆。她不想再等了，起身离开。没有人注意到她。

# 思路（只用于理清逻辑，不写进提示词）
声明：A 是一位女性，来自参考图 1，本段全身可见。B 是邻桌两位客人，本段在背景里。
S0：A 坐在靠窗的桌边，双手放在桌面，看向窗外。B 坐在邻桌。
a1：A 双手撑桌站起来 → A 站在桌边。
a2：A 转身面向门口 → A 背对窗户站着。
a3：A 走向门口 → A 停在门前。

# 写进提示词
她坐在靠窗的桌边，双手放在桌面，看向窗外。邻桌坐着两位客人，低头看着自己的杯子。她双手撑桌站起来，站在桌边。她转身面向门口，走到门前停住。
环境声：咖啡机的蒸汽声，杯碟轻碰。
配乐：none。
```

「没有人注意到她」是否定句，改成邻桌客人低头看杯子；邻桌客人在思路里先声明过，才能写进正文。
